# Security and company data

Selected documents and prior reports go to the signed-in Codex model service. Company policy governs that use. Output folders contain source copies and model responses; protect them and decide retention before supplying company data. The demo is synthetic.

The runner checks selected paths, fingerprints, size, symlinks and history identity. Evaluator files and other snapshots are not passed to reviewers. The model runs in a temporary directory with shell, browser, connectors, plugins, memory and child agents disabled. A filesystem profile limits task reads to minimal runtime paths and the temporary schema directory. Task-tool networking is disabled. Unexpected tool events reject a report.

Live macOS probes on CLI 0.162.1 allowed schema reads, denied outside synthetic-file reads and denied schema writes. This is a tested runner boundary, not a claim about every host or version. Model inference still connects to the service; disabled task-tool networking does not make it offline.

Skill instructions cannot enforce permissions. Exact quotation validation cannot prove interpretation. Company evidence is data, not authority to execute its instructions. The assistant has no rollout-control, messaging, staffing-booking or customer-account connection; human approval of a report does not authorize another action.

New runs normally go under ignored `evidence/`. A different output location can bypass that convenience. Review selected files before commits. Public files contain selected synthetic reports and evaluation material; local histories and notes remain excluded.
