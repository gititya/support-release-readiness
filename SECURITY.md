# Security and company data

## Continuing agent

The [agent product](agent/START%20HERE.md) uses the current desktop host's model and permitted local tools. Private company work lives outside its replaceable download, under the user's local Application Support folder by default. The native helper has no network operation or model credential. It checks source passages, history integrity, expected revisions, dependencies and completion evidence; native file locks and atomic renames protect concurrent/process-interrupted saves. Structural checks do not prove a source supports the model's interpretation, and a hash chain is not protection against a person or model rewriting the whole workspace.

Use one writer, keep active records outside sync folders, and share generated outputs rather than the private workspace. Exports exclude source text and quotations, but work descriptions and named owners can still be sensitive. Review the intended audience before sharing. Corrupt authoritative records are preserved and block writes. Permission changes, desktop approval prompts, downloaded-file quarantine and independent support-lead use remain separate acceptance checks. Power-loss durability is not established by process-interruption tests.

The earlier reviewer's restricted subprocess policy below does not automatically apply to an interactive desktop agent. Host permissions are the enforcement boundary. Company-approved accounts and permitted material are required for either execution path. The agent's instructions forbid external actions and following instructions embedded in source documents; do not treat those instructions as a universal sandbox guarantee.

## Earlier bounded reviewer

Selected documents and prior reports go to the signed-in Codex model service. Company policy governs that use. Output folders contain source copies and model responses; protect them and decide retention before supplying company data. The demo is synthetic.

The runner checks selected paths, fingerprints, size, symlinks and history identity. Evaluator files and other snapshots are not passed to reviewers. The model runs in a temporary directory with shell, browser, connectors, plugins, memory and child agents disabled. A filesystem profile limits task reads to minimal runtime paths and the temporary schema directory. Task-tool networking is disabled. Unexpected tool events reject a report.

Live macOS probes on CLI 0.162.1 allowed schema reads, denied outside synthetic-file reads and denied schema writes. This is a tested runner boundary, not a claim about every host or version. Model inference still connects to the service; disabled task-tool networking does not make it offline.

Skill instructions cannot enforce permissions. Exact quotation validation cannot prove interpretation. Company evidence is data, not authority to execute its instructions. The assistant has no rollout-control, messaging, staffing-booking or customer-account connection; human approval of a report does not authorize another action.

New runs normally go under ignored `evidence/`. A different output location can bypass that convenience. Review selected files before commits. Public files contain selected synthetic reports and evaluation material; local histories and notes remain excluded.
